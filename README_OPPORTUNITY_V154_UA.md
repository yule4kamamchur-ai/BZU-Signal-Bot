# BZU MULTI v15.4 Adaptive Opportunity Intelligence

Дослідницьке PAPER-оновлення на базі завантаженого `BZU-Signal-Bot-main (4).zip` (v15.3, стан 28.11.2026 10:25). Не замінює журнал, state, історію чи параметри вже відкритих угод. Лише симуляція, не торгує на біржі. Немає доведеної прибутковості.

## Встановлення

1. Зробити резервну копію репозиторію. Замінити/додати всі файли патча за шляхами (включаючи приховану `.github`). Не замінювати `multi_scanner_memory.json`, `multi_scanner_state.json` та інші журнали. Не запускати одночасно worker і GitHub-сканер на одній пам'яті.
2. Для GitHub залишити cron-job.org з існуючим URL `main.yml/dispatches` та інтервалом 3 хв. `main.yml` містить лише `workflow_dispatch`, старого cron немає. Якщо вже існує змінна `MEXC_SCAN_INTERVAL_SEC=300`, виправити на `180`; це діагностичний очікуваний інтервал, а не планувальник. Запустити один ручний цикл та перевірити версію й `health`.
3. У UI з'являються статистика SHADOW, фаза/волатильність, E[R] та ефективна кількість аналогів. SHADOW не включається в реальний PAPER PnL.
4. Для справді постійного процесу: існуючий Docker worker тепер налаштовано на 60 с, таймаут 50 с. Спочатку встановити `BZU_SERVER_MODE=WORKER` у GitHub і зупинити cron-job.org, скопіювати поточну пам'ять та state в `./data`, потім `docker compose up -d --build`. Дашборд локального worker — `http://127.0.0.1:8080/`, `/healthz` для моніторингу. Якщо VPS, потрібна окрема безпечна публікація дашборда. Це хвилинний polling, не серверний tick WebSocket і не гарантія вчасного виконання. GitHub сам по собі залишиться 3-хвилинним зовнішнім dispatch із можливою чергою.

## 16 пунктів: реалізація та межі

1. Shadow Ledger: усі детектовані кандидати, перевірені вікна, пропущені імпульсні M1-вікна (діагностика), фінальне рішення слотів. Моделює лише придатну геометрію, з поточного моменту, окремо для доступних маршрутів. SL/TP статичні, не всі альтернативні геометрії; не заповнює минулі тики. Моделі не враховують funding. LIMIT — консервативний проксі проникнення, не реальне виконання. Невідомий порядок або пропуски позначаються. Rolling retention: 500 pending, 4000 resolved, 3000 observations, dedup 48h; це не безстроковий архів. Дані зберігаються в існуючій пам'яті.
2. Історична калібрація: новий `mexc_replay_v154.py` + ручний GitHub workflow `replay_mexc_v154.yml`. Завантаження M1 через офіційний API порціями (кеш), повністю закриті старші свічки, однакова історія. Реальний прогін ще не виконано: середовище аудиту не має DNS до MEXC. Не використовувати штучний набір для калібрації.
3. Expected Net R: згладжене емпіричне середнє чистого R за напрямком, сімейством, режимом та активом. Рейтинг = E[R] + малий обмежений додаток за якість/RR. Не трактувати E[R] як доведену перевагу. Видалений абсолютний поріг 76; технічна геометрія, свіжість, структура, дублювання, контекст M1 та бюджет лишаються захистом.
4. Opportunity Memory: зберігає підтверджені M5-пробої до 90 хв, перевіряє інвалідацію й дозволяє новий ретест, навіть якщо первісна свічка вже поза двосвічковим вікном. Не підміняє час входу старим.
5. Market State: локальний та старший напрямок, фаза (IMPULSE/PULLBACK/EXHAUSTION/COMPRESSION/BALANCED), ATR-волатильність, злам і спред-проксі ліквідності. Не order-book модель.
6. Momentum: початок розширення та продовження, оцінка попередньої хвилі і виснаження. Сильний ціновий пробій допускає помірний RVOL нижче старого порогу; без актуального тригера вхід не створюється.
7. Пробій/пастка: довше вікно підтвердженого пробою, збереження рівня до інвалідації, ретест, цінове повернення. Це евристичні ознаки, не навчений класифікатор true/false.
8. MARKET/LIMIT: альтернативна пасивна ціна, структурна геометрія, окремі витрати й невеликий штраф за ризик невиконання. Немає достовірного прогнозу fill probability.
9. Position Intelligence: перевірка поточної протилежної M5/M15 хвилі після відкриття; достроковий THESIS_DECAY лише на актуальній котировці, не на минулих барах. Відкриті старі угоди не переоформлюються.
10. TP1 chronology: курсор і час дії нового SL. Внутрішньохвилинний quote TP1 більше не застосовує BE до старого wick; невідомий шлях позначено окремо.
11. TP1/Runner/Alpha decay: 30% частково для імпульсних, 40% для інших, поріг ~0.9–1.25R за контекстом, runner та структурний SL; 45/75 хв для швидкої ідеї або 90/150 хв для повільної при застої. Дослідницькі параметри; не оптимізовані на історії.
12. Окреме LONG/SHORT навчання з першого придатного епізоду, prior 8 псевдоспостережень (0R/0.5), не 40/12. Вага нової paper-угоди 1, старої v15.3 0.25, live shadow 0.35, historical replay 0.25, historical shadow 0.15; далі зважується схожість. Невідомий funding додатково зменшує вагу. Дедуп подій; старий OKX та невідомий внутрішньобарний шлях виключені. Швидкий старт НЕ означає достатню доказовість. Метамодель не блокує за ймовірністю.
13. Портфель: базова третина спільного бюджету, після ефективних 8 аналогів та позитивного E[R] частка може зростати до половини невикористаного бюджету. Не збільшує спільний ризик/плече; вже відкриті розміри не змінені. Це експериментальний розподіл, не оптимізація Kelly.
14. Relative Strength: причинна оцінка beta за синхронними M15 до останньої години, зі згладженням та fallback, якщо недостатньо варіації. BTC не є безумовним вето.
15. Витрати: окремі maker/taker та slippage на вхід/вихід, TP1 зважений, консервативна оцінка spread. Публічна історія settled funding для нових активних угод, M1 proxy ціни розрахунку, дедуп, позначка недоступності. Немає приватних тарифів або реальних виконань рахунку; historical replay funding наразі не враховує. Не вважати 0% maker автоматично 0% виходу. Дефолти PAPER залишені 0.02% maker/taker, 0.01% slippage; налаштувати `MEXC_MAKER_FEE_RATE`, `MEXC_TAKER_FEE_RATE`, `MEXC_SLIPPAGE_RATE` за рахунком, окремий asset override наприклад `MEXC_LINK_TAKER_FEE_RATE`. Для API торгівлі окремо перевірити тарифи: MEXC оголошувала 0.06% maker / 0.08% taker з 01.06.2026; це окремий stress-сценарій, не ваш підтверджений тариф. https://www.mexc.com/announcements/api-updates/futures-19
16. Worker: 60-секундний безперервний цикл на незалежному сервері; зовнішній dispatch 180 с залишається без змін. Tick monitoring не додано; серверний worker треба реально розгорнути.

## Історичний тест і швидкий старт навчання

У GitHub Actions → `BZU v15.4 historical calibration (research only)` → Run workflow. Default: train 07.11–21.11.2026 UTC, holdout 21.11–28.11.2026 UTC; додаткові попередні свічки для warmup. Можна встановити довший період. Потрібен доступ GitHub runner до MEXC, дані всіх 8 символів і tick metadata. Для порівняння заповнити optional `baseline_ref` точним SHA попередньої v15.3. Кешується історія; не змінює live memory, не пушить нічого. Після завершення artifact `mexc-v154-research`: звіт v15.4, за наявності baseline — звіт v15.3, окремий `mexc_calibration_v154.json` з навчальних результатів до split (не holdout). Перевірити звіти, покриття і якість. Якщо прийнятно, додати саме цей файл у корінь репозиторію для швидкого старту. Не копіювати будь-який синтетичний prior. Імпорт зі слабкою вагою, статус невалідований; нові угоди далі оновлюють оцінки.

Локально (ті самі дані, без живих змін):
```
python mexc_replay_v154.py --data mexc_replay_cache --start 2026-11-07 --split 2026-11-21 --end 2026-11-28 --download --output MEXC_REPLAY_REPORT.json --export-prior mexc_calibration_v154.json
python mexc_replay_v154.py --engine-dir /path/to/v15.3 --data mexc_replay_cache --start 2026-11-07 --split 2026-11-21 --end 2026-11-28 --output MEXC_BASELINE_REPORT.json
```
Для sensitivity/stress: повторити на тих самих CSV з `MEXC_MAKER_FEE_RATE=0.0006 MEXC_TAKER_FEE_RATE=0.0008`, іншим spread (`--spread-bps 5`) та затримкою (`--interval 300`). Replay не відновлює L2 або реальні bid/ask; quote = ціна відкриття доступної хвилини + припущений спред. Хронологічний prequential holdout: нові минулі завершені епізоди доступні, майбутні ні; це не заморожена модель. Статичний депозит 100 USDT, витрати оцінено, funding пропущено. Відкриті на кінець угоди та перехідні між train/holdout не зараховуються в завершений holdout PnL. `seven_day_holdout` містить кожні 7 діб, включно з нульовими угодами. Не вважати один успішний тиждень підтвердженням стабільних 20%.

## Перевірка в цьому аудиті

- 71 Python-тест виявлено: 70 успішно, 1 пропущено (залежить від старого знімка 27.11). Дві старі fixture-перевірки адаптовані до нової версії та 60-секундного worker.
- 7 попередніх JS-перевірок (2 Node suites) пройдено; синтаксис Python/JS та YAML перевірено.
- На штучних 8 рядах (40 циклів по 3 хв для кожної версії) v15.3 та v15.4 replay обробили всі 7 активів на кожному циклі; 0 закритих угод. Це smoke-тест сумісності, НЕ backtest, жодних synthetic priors у патчі.
- Реальна історія поточного архіву: 8 завершених v15.3, 3 wins, 37.5%, -1.1604R, -1.78 USDT; 7 OBSERVED_M1. Немає жодної закритої v15.4. 80 M5/M15 без обсягів, M1 відсутні в збереженому стані. DNS API недоступний в аудиті. Ціль 20 USDT/тиждень не доведена.
- Не було живого розгортання та перевірки приватних тарифів. Не збільшувати ризик для компенсації від'ємної expectancy.
