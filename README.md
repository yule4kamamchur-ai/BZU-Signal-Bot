# BZU · v12.35 Position Guard

Рушій підтримує два типи виконання паперових сигналів для BZ-USDT-SWAP. Трендові плани проходять перевірку структури 1H/4H та геометрії органічного ризику.

| Тип | Коли спрацьовує | Ціна входу |
| --- | --- | --- |
| LIMIT | Підтверджена зона за трендом на відстані $0.08–2.20, оцінка від 52 | Верхня межа для LONG і брейкерів, нижня для інших SHORT. Для BOS використовується відкат на 30% тіла. |
| MARKET | Котирування в зоні з допуском $0.08 або свіжий тест за останні шість закритих M5 чи три M15 з відбоєм до 0.45R, оцінка від 52 | Поточний ask для LONG або bid для SHORT |
| MARKET після пробою | Свіжий закритий імпульсний пробій за трендом, оцінка від 60, дистанція до 0.45R | Поточний ask або bid |

Рушій використовує одну активну позицію або лімітку на інструмент. Після підтвердженого MARKET на поточному циклі записує `OPEN`, а для LIMIT записує `PENDING`. Журнал і дашборд отримують один і той самий запис. GitHub Actions запускає штатний цикл кожні 15 хвилин. Ціна на сайті може оновлюватися між циклами.

ATR 1H розраховується за 14 закритими годинними свічками з резервною оцінкою за M15. ADR усереднює до 14 повних діб UTC. Стоп враховує ATR, ADR, відсоток від входу, волатильність сесії та структурну межу. Якщо придатного рівня 1H/4H немає, підтверджений трендовий план може використати дальню межу своєї зони з буфером 0.25 ATR 1H. Максимальна межа ризику становить більше з $2.10 і 2.20% входу. Структурний стоп, що виходить за цю межу, блокує план.

Для трендових планів TP1 шукається у вікні 1.10–1.45R. За відсутності придатного рівня використовується проєкція 1.10R. Ближня ліквідність до 1.05R зберігається як контрольний рівень. TP2 шукається на 4H/D1 у вікні 1.80–2.25R з резервною проєкцією 1.90R. Свіжа сильна зустрічна зона перед TP1 блокує план. Протестовані зони залишаються в аналізі. Після фіксації 50% на TP1 перенесення стопа в беззбиток з урахуванням комісій потребує підтвердження M5.

## Захист відкритої позиції

Рушій відстежує MFE, MAE та кількість повних 15-хвилинних інтервалів від входу. Чинні SL і TP обробляються першими. Нижченаведені правила діють до часткової фіксації TP1.

- Після піку від +0.55R і 90 хвилин вихід спрацьовує при поверненні в межі ±0.10R від входу. Вихід рахується за спостереженою ціною з поточними витратами.
- Після шести годин з піком нижче +0.60R рушій виходить на ретесті входу або підтягує SL за підтверджений свінг останніх двох годин. Новий рівень обмежує ціновий ризик до 0.35R.
- Після підтвердженого зустрічного M15 BOS або CHoCH вихід можливий на наступному ретесті в межах −0.10R…0R.
- Після чотирьох годин позиція в межах ±0.15R може поступитися свіжому підтвердженому MARKET-сетапу A+. Для зміни напряму потрібен закритий структурний злам. Паперовий журнал спочатку закриває попередню позицію.

Між циклами дашборд показує оцінку MFE та MAE за отриманими тиками. Остаточні метрики, виконання та зміни стопа підтверджує Python-рушій. Розклад GitHub Actions становить 15 хвилин.

Підтверджений свіп із тінню від 45% і поверненням тіла за рівень може скасувати локальний конфлікт. Фільтр підтвердженого протилежного макротренду діє. Вікно M15 Sweep → BOS становить до десяти свічок. Для дедуплікації близьких планів порівнюються відстань до входу та підтверджений свінг між входом і стопом. Індекс близькості не є оцінкою ймовірності виконання.


## Оновлення через GitHub

Завантажте файли з `01_UPLOAD_TO_REPO_ROOT` у корінь репозиторію, а `main.yml` із `02_UPLOAD_TO_WORKFLOWS` у `.github/workflows`. Запустіть **Actions → Run workflow** і дочекайтеся `deploy-pages`. Цикл оновить стан за поточним журналом. Результати історичних паперових прогонів містяться в `DETAILS` малого пакета.

```sh
python bot_oneshot.py --self-test
node --check live_terminal.js
node test_live_terminal_ui.cjs
```
