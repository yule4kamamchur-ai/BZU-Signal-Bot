# BZU Signal Bot v12.4 — лімітні сетапи на 15m, 1h і 4h

Виправлено сканування сетапів та інформативність повідомлень. Це версія генератора лімітних торгових сигналів із супроводом за свічками. Автоматичного надсилання заявок на OKX у коді немає.

## Чому попередній бот пропускав входи

- 24 оригінальні детектори запускалися лише на контексті 15m. 1h/4h використовувалися як напрямок, а не як окремий графік сетапу.
- Після кожного детектора додатково вимагалися контроль і відхід на 3m. Для вже сформованого рівня відкату або межі діапазону така загальна умова могла відкладати ліміт до зайвого підтвердження.
- Повідомлення не містило поточної ціни, відстані до рівня, умов формування чи конкретної причини відмови.

## Що робить v12.4

1. Запускає всі 24 оригінальні детектори на кожному з трьох графіків: **72 окремі перевірки** за цикл. Умови й рівні будуються з реальних свічок відповідного таймфрейму. Молодший графік: 15m → 3m, 1h → 15m, 4h → 1h. Оригінальні назви збережено; зокрема історичний ідентифікатор `DIRECTION_FLIP_15M` отримує окреме поле таймфрейму, коли оцінюється на 1h/4h.
2. Додає список власних спостережуваних умов для кожного сетапу. Сценарій видно ще до повного формування: виконані умови, невиконані умови, опорний рівень і відстань ціни.
3. Активує лімітний сигнал **до повернення ціни на рівень**, якщо оригінальний детектор підтвердив умови, ліміт не перетинає спред, рівень не був відвіданий після першого спостереження, є структурний SL/TP і достатній потенціал після витрат. Дотик ціни не є додатковою умовою для виставлення такого ліміту.
4. Зберігає максимум два місця для невиконаних лімітів і відкритих сигналів разом. Дублікати близьких рівнів об’єднуються. Протилежний новий сигнал не створює хедж. Частковий TP не звільняє місце.
5. Пояснює кожну відмову: замало простору до цілі, занадто широкий стоп, непідтверджений розворот проти обох старших графіків, надмірна волатильність, денний ліміт, зайняті місця тощо.
6. Повідомляє ціну зараз, сетап і його таймфрейм, LONG/SHORT, вхід, SL/TP, відстань до входу у %, наближення після активації, строк ліміту, результат і досягнуті TP. При відсутній/застарілій ціні показує «недоступна» й не обчислює удавану відстань.
7. Прибирає повторювані банери PAPER і порожню фразу «нових входів немає». Статус називається «лімітний сигнал», щоб не видавати модельний облік за підтверджене біржове виконання.
8. Dashboard містить таблицю 24 × 3: готовність, рівень, відстань, очікувана історична оцінка, причина очікування. Всі 72 оцінки зберігаються в поточному стані й журналі.

## Що означають відсотки

- **Умови 75% (3/4)**: виконано три з чотирьох спостережуваних умов конкретного сценарію. Це не ймовірність прибутку. 100% умов також не скасовує перевірок ризику та вільних місць.
- **До входу 0.54%**: `abs(поточна ціна − вхід) / поточна ціна × 100`.
- **Наближення 73%**: відстань до входу скоротилася на 73% від відстані в момент активації. Значення обмежено 0–100%; якщо ціна віддаляється за початкову точку, показується 0%. Для старих планів без збереженої початкової ціни цей показник не вигадується.
- **Оцінка win rate**: згладжена частка виграшів після комісій у минулих незалежних завершених сценаріях. Порівнюються однакові таймфрейм, напрямок, режим і HTF-контекст. За відсутності 40 відповідних незалежних результатів показується «н/д, n/40». Якщо оцінка походить із сім’ї, це прямо зазначено. Це не гарантована ймовірність наступної угоди.

Навчальні результати старої політики v12.3 архівуються, бо змінився момент входу. Старі угоди лишаються в історії. Їх не використовують як докази win rate нової політики. Корельовані сигнали одного рівня не множать вибірку.

## Строки для нових планів

| Графік сетапу | Максимальний вік для нового сигналу | TTL ліміту | Максимальний супровід після входу |
| --- | ---: | ---: | ---: |
| 15m | 180 хв | 120 хв, до кінця сесії | 360 хв, до кінця сесії |
| 1h | 720 хв | 480 хв | 1440 хв |
| 4h | 2880 хв | 1920 хв | 5760 хв |

Значення масштабуються від налаштувань 15m за кількістю хвилин таймфрейму. Деякі оригінальні детектори мають коротший строк формування рівня; він також масштабується. **SL, TP, TTL і супровід уже наявних планів не переписуються.** Сесійні рівні беруться з фактичних 15m-свічок; чотири 4h-свічки не використовуються як opening range. SMT доступний лише там, де є синхронна реальна порівняльна історія 15m.

## Як оновити GitHub

1. Збережіть резервну копію актуальних `last_signal_v6_4.json` і `signal_journal_v6_4.json` із свого репозиторію.
2. Розпакуйте ZIP. Оновіть код поверх існуючого репозиторію, включно з **новим `setup_scanner.py`**, `bot_oneshot.py`, `full_limit_engine.py`, `signal_quality.py`, `research_validate.py`, `index.html`, усіма `test_*.py`, `setup_preservation_manifest.json` і `.github/workflows/main.yml`.
3. **Не видаляйте й не замінюйте актуальні файли стану та журналу.** Їхніх копій у цьому ZIP немає. Обидва зайняті місця й старі рівні зберігаються після перезапуску.
4. Secrets `TELEGRAM_TOKEN` і `TELEGRAM_CHAT_ID` залишаються. Actions → General → Workflow permissions: Read and write permissions.
5. Запустіть Actions → Run workflow. Перевірте успішні тести, 72 перевірки в dashboard і повідомлення з поточною ціною та конкретними рівнями.

Розклад збережено: сканування/супровід кожні 5 хв, Telegram кожні 15 хв. Події тихих запусків входять у наступний звіт. GitHub Actions може запускати schedule із затримкою.

## Перевірка

```bash
python -m py_compile bot_oneshot.py full_limit_engine.py signal_quality.py setup_scanner.py research_validate.py
python bot_oneshot.py --self-test
python bot_oneshot.py --legacy-self-test
```

Точні результати перевірок наведено у `VALIDATION_REPORT_UA.md`. Синтетичні тести доводять поведінку коду, а не прибутковість. У завантаженому архіві немає живого журналу або повної ринкової історії, тому реальний очікуваний win rate для кожного сетапу зараз обчислити неможливо; 70% не підтверджено.

Для справжніх заявок OKX потрібна окрема реалізація приватного торгового API, явно заданий розмір/ризик позиції та звірка статусів біржі. Поточне оновлення виправляє сканер, лімітні сигнали й повідомлення. Офіційна специфікація: https://www.okx.com/docs-v5/en/#order-book-trading-trade-post-place-order
