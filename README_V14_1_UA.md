# BZU v14.1 Real-Time Brain

## Оновлення

Розпакуйте ZIP у корінь наявного репозиторію із заміною файлів. У комплекті файли коду й тести. Історія угод, файли стану та налаштування секретів зберігаються в поточному середовищі.

**GitHub Actions і Pages.** Запустіть наявний workflow один раз вручну. Він опублікує дашборд і новий формат зліпка. У відкритій вкладці браузер читає публічний потік OKX і перераховує сканер кожні 3 секунди. GitHub Actions продовжує сканувати за своїм 5-хвилинним розкладом. Звіт має один слот на 15 хвилин і може надійти пізніше, якщо GitHub затримав запуск.

**Серверний воркер.** На постійному хості встановіть змінну репозиторію GitHub `BZU_SERVER_MODE=WORKER`. Підготуйте `.env` з чинними змінними `TELEGRAM_TOKEN` та `TELEGRAM_CHAT_ID`. Перед першим запуском перенесіть чинні `last_signal_v6_4.json` і `signal_journal_v6_4.json` в `data/` біля `compose.yaml`. Запустіть `docker compose up -d --build`. Дашборд воркера слухає `http://127.0.0.1:8080` на цьому хості. Для віддаленого доступу використайте наявний HTTPS-проксі або SSH-тунель. Воркер запускає перевірку на 3-секундних інтервалах, якщо збір даних і обробка попереднього циклу завершились. Регулярний звіт планується після короткої затримки на публікацію свічки, один на чверть години.

## Стан і виконання

- Браузер показує PAPER-переходи за спостереженими котируваннями bid/ask. Угода, проведена лише у вкладці, має позначку PAPER. Сканер браузера переоцінює M15 і M5 та власні зони, а серверний сканер продовжує застосовувати ширший набір правил ICT.
- Сервер зберігає рішення та звіряє High/Low закритих M1 у часовому порядку. Якщо ліміт міг виконатися у ще відкритій хвилині, сервер підтверджує його стан перед записом наступної угоди. Окремий офлайн-аудит може використати закриті M5, коли точнішої серії немає.
- У браузері невиконана лімітка скасовується після руху на 0.75R чи до ближчого TP1. Для заміни за трендом потрібні понад 1.0 ATR і ближчий підтверджений план. На сервері поріг заміни становить 0.70 ATR.
- Для імпульсного MARKET входом є поточний ask для LONG або bid для SHORT. Перевірка вимагає до 0.65 ATR від підтвердженого рівня та щонайменше 1.40R до цілі за ціною входу. На +1R браузер фіксує 50% у PAPER і пересуває стоп на +0.15R з округленням до тика.
