# BZU v14.3 Pro Cockpit

Розпакуйте ZIP у корінь наявного репозиторію зі збереженням шляхів. Архів містить код, тести й інструкцію. Чинні файли стану та журналу залишаються у вашому середовищі.

## Дашборд і живий цикл

- У FLAT графік показує свічки. Радар дає один пріоритет та чергу з рівнями й умовами активації.
- Після LIMIT_PLACED або ENTERED графік показує POI, ризик, ціль і маркер входу. BSL та SSL прив’язані до доступних підтверджених рівнів ліквідності. Після Scale-Out лінія SL відображає чинний захисний стоп.
- Відкрита вкладка запитує тікер, M5 і M15 в OKX кожні три секунди. Сканер використовує закриті свічки для підтвердження структури та живі bid/ask для активації. Холодний старт можливий за недоступного серверного зліпка.
- Браузерна мітка MARKET вимагає до 0.18 ATR для тесту рівня або підтвердженого імпульсу. Ліміт може активуватися в межах 0.85 ATR за наявності простору до цілі. Стан симуляції PAPER зберігається локально й звіряється після появи серверних даних.
- На сервері валідний тест до 0.20 ATR спрямовується в MARKET. Для нових LIMIT і MARKET потрібні 1.35R. Скасування через структурну перешкоду враховує рівні, що підтвердилися після виставлення лімітки, і спрацьовує нижче 1.05R від її фіксованого входу.

Браузер відтворює розрахунки EMA і ATR, використовує VWAP та локальні детектори M5/M15. Сервер додатково враховує старші таймфрейми, власні перевірки й послідовність заповнення ордерів. Через це окремі PAPER-сигнали можуть різнитися.

## Запуск і перевірки

На GitHub Actions запустіть наявний workflow вручну для першої публікації v14.3. Розклад GitHub у цьому репозиторії має п’ятихвилинний інтервал. За постійного воркера перебудуйте контейнер через `docker compose up -d --build`. Інструкція налаштування воркера є в `README_V14_1_UA.md`.

```sh
python3 -m unittest test_v142_organic_execution test_v141_realtime test_v14_trader_brain test_pending_limit_lifecycle
node test_live_terminal_ui.cjs
```
