# v15.8.2 — виправлення історичного replay H1/M15

Причина: запитаний історичний період міг не відповідати реально отриманій історії M1. Попередній завантажувач повідомляв лише кількість свічок. Помилка `Insufficient H1 warmup` була правильною захисною перевіркою, а не несправністю торгового алгоритму.

Замінити `replay_h1_portfolio.py`, `mexc_replay_v154.py`, `.github/workflows/replay_h1_v158.yml`. Новий `test_mexc_replay_coverage.py` — автоматизовані перевірки. Не змінювати основний `main.yml`, дані, пам'ять чи налаштування cron-job.org.

GitHub Actions: BZU v15.8 H1 M15 portfolio research (PAPER only), Run workflow. Для першого прогону: Start 2026-11-08, End 2026-11-28, Profile MIXED_PEAK_RANGE, Coverage mode available, Spread bps 0. Витрати 0.03% на сторону збережені.

- `available`: дозволяє використовувати лише спільний доступний період усіх вибраних активів після прогріву; обрізані межі округлюються до цілих UTC-днів. Якщо скорочений період менший за 7 днів, запуск завершується помилкою.
- `strict`: вимагає заданих дат та достатнього прогріву. Внутрішні пропуски не заповнюються; звіт містить їх кількість. Кінець виключний.
- 31 закрита H1-свічка для трендових профілів, 21 закрита M15 для range-профілів. Збережено торговий алгоритм і умови допуску сигналів.
- `H1_M15_COVERAGE.json`: початкові, фактичні дати, кількість доступних свічок, прогрів та пропуски. Формується після читання наявних валідних CSV, також при недостатньому прогріві або кінцевій даті. Якщо API недоступне або файл невалідний до перевірки покриття, дивитися лог GitHub.
- `H1_M15_PORTFOLIO_REPORT.json`: фінансовий звіт із `coverage_window`. Скорочений тест не є 180-денним тестом.
- Порожні/невалідні кешовані відповіді повторно запитуються; валідні непорожні частини збережено. H1/M15 не використовує BTC для сигналів, тому новий replay завантажує лише потрібні активи. Основний M1/M5 replay і надалі за замовчуванням завантажує BTC.
- Кеш GitHub зберігається окремим кроком навіть якщо фінансова симуляція зупинилася. Новий ключ враховує номер запуску та повторної спроби.

Перевірка: `python -m unittest discover -p 'test_mexc*.py'` — 108 тестів, 107 успішних, 1 пропущений. Тести охоплюють скорочення періоду, строгий режим, відсутність штучних свічок, повторне завантаження порожнього кешу, збереження звіту та незалежність від торгового стану. Реальний GitHub/MEXC прогін не виконано. Не гарантується, що API поверне потрібні 180 днів M1; якщо історія обмежена, потрібен окремий повний історичний архів.
