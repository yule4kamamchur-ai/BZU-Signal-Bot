# BZU v14.4.2

Патч для v14.4.1. Розпакуйте архів у корінь репозиторію зі збереженням шляхів і перенесіть файли одним комітом. GitHub запускає `.github/workflows/main.yml`. `WORKFLOW_main.yml` містить ідентичний текст для ручного перенесення. ZIP містить код, workflow та тести. Поточні ордери і журнал залишаються у файлах стану встановленої версії.

## Правила входу

- Свіжий `FVG_PULLBACK` може отримати LIMIT до першого торкання за спокійного підходу з тілами M15 менше ніж `0.80 ATR`. Нейтральний підхід до `1.00 ATR` проходить звичайні перевірки зони. Після зустрічної закритої M15 з тілом понад `1.00 ATR` поблизу зони потрібен закритий відбій M15. Якщо зона вже втратила свіжість або ціна досягла цілі, бот оцінює наступний сетап за його власним підтвердженням.
- Доказ `BOS_IMPULSE_BREAKOUT` для трендового ретесту діє до 90 хвилин або до 120 хвилин за узгодженого 1H і 4H, поки закриття свічок підтримують пробиту структуру. Для MARKET діє вимога свіжої свічки підтвердження та актуальної ціни виконання.
- Новий LIMIT діє до 60 хвилин у діапазоні, до 90 хвилин у тренді та до 120 хвилин за збігу 1H і 4H із напрямком входу. Строк може бути коротшим, якщо спливає початковий якір. Для нових трендових LIMIT пропущений вхід фіксується на фактичному TP. Структурна інвалідація і правило раннього NY діють протягом очікування.
- Підтверджений MARKET має пріоритет над очікуючим LIMIT тієї ж сторони. Для зміни сторони потрібен підтверджений структурний розворот. У PAPER рушій спочатку звіряє можливе виконання лімітки. У DEMO/LIVE він чекає на підтвердження стану попереднього ордера та перевіряє MARKET-сигнал на наступному скані. Заповнення старої заявки має пріоритет перед заміною.
