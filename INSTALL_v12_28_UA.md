# v12.28 Pro Quant Engine

## Встановлення на GitHub без сотень файлів

1. Розпакуйте `BZU_v12_28_SMALL_UPDATE.zip` на комп'ютері.
2. Відкрийте папку `01_UPLOAD_TO_REPO_ROOT`. Виділіть **20 файлів усередині** (`Command+A` на Mac). На GitHub у корені наявного `BZU-Signal-Bot` виберіть **Add file → Upload files**, перетягніть ці файли та збережіть **Commit changes**. Саму папку або ZIP завантажувати не потрібно.
3. На GitHub відкрийте **`.github/workflows`**, виберіть **Add file → Upload files**. Завантажте туди **`main.yml`** із папки `02_UPLOAD_TO_WORKFLOWS`, збережіть **Commit changes**. Кореневий `WORKFLOW_main.yml` — лише копія; він не замінює цей крок.
4. Після обох збережень відкрийте **Actions → Run workflow**. Проміжний запуск зі змішаними версіями може зупинитися; запустіть ще раз після другого commit.
5. Дочекайтеся успішного циклу та публікації Pages, оновіть дашборд через **Command+Shift+R**.

Не видаляйте решту репозиторію. Компактний пакет не містить журналів, ринкових архівів, контрольних точок повідомлень або `live_state.json`: актуальний зліпок сформує наступний реальний цикл. `DETAILS` містить діагностику пакета; завантажувати її на GitHub не потрібно.

## Повні плани зон

`setup_scanner.calculate_zone_trade_plan()` викликається при формуванні публічного зліпка для кожної валідної зони. Потрібні узгоджений напрямок, додатні межі, відомий час та закриті свічки для ATR. Некоректним даним не підставляються вигадані ціни; причина потрапляє в `unplanned_zones`.

Для зони без готового повного плану:

- **Entry:** проксимальна межа + $0.03 для LONG або − $0.03 для SHORT, із округленням за тиком. Для ширини понад `1.5 × ATR15` — середина повної зони (Equilibrium).
- **SL:** дистальна межа − `0.25 × ATR15` для LONG або + `0.25 × ATR15` для SHORT, з округленням назовні.
- **TP1:** найближча відома сприятлива структурна ліквідність мінус один тик до неї; за її відсутності — проєкція щонайменше `1.45R`.
- **TP2:** наступний сприятливий структурний рівень або проєкція `2.40R` (за потреби далі TP1). Джерело цілі передається окремо.

Близька перешкода не пропускається задля красивого R:R: недостатній простір залишає план довідковим. Зберігаються чинні межі ризику та дистанції; далека зона не перемагає близьку робочу лише через бал.

Повна коректна геометрія плану рушія переноситься цілком. Неповні параметри перераховуються як єдине ціле, без змішування Entry одного плану зі стопом іншого. Наявні журнальні ордери та позиції зберігають контрактні ціни й цикл супроводу. Нова проєкція TP1 1.45R застосовується до нових планів; старі цілі не мігрують.

## Прозорий бал 0–100

| Критерій | Бали | Доказ |
|---|---:|---|
| Відповідність режиму | 25 | Напрямок збігається з домінантним трендом |
| Свіжість | 20 | Немає спостереженого тесту після формування; історія покриває період без пропусків |
| Старший ТФ або sweep | 20 | Зона 1H/4H або sweep із відомим часом |
| Displacement/FVG | 20 | FVG або спостережений спрямований вихід біля формування |
| Простір | 15 | R:R TP1 ≥1.4; найближча ліквідність не ближча за 1.4R |

Бали додаються тільки за виконані критерії. Неповна історія не отримує бонусу свіжості. Результат дискретний; це евристичне ранжування, а не ймовірність виграшу. Розкладка доступна в радарі та підказці таблиці. Бал рушія/журналу збережено окремо.

**A ≥65** — тактика прямої лімітки після фінального допуску рушія. **B+ 58–64** — спостереження за реакцією M5. **C <58** — повний довідковий план без сигналу входу. Обмеження ризику, простору, дальності та протилежного тренду мають перевагу над класом. Коли робочих кандидатів немає, радар може показати найближчий повний довідковий план із причиною обмеження.

## Impulse Brake та HYBRID

Гальмо оцінює одну найсвіжішу закриту M15 або новішу повну M5 поточної чверті години. Базовий ATR виключає оцінювану свічку. Блокування потребує одночасно:

1. Діапазону свічки понад `1.8 × ATR15`.
2. Несприятливого тіла щонайменше 70% діапазону.
3. Тіні з боку стопа не більше 10% діапазону.
4. Закриття не далі `0.25 × ATR15 + пів тика` від фактичного SL у напрямку підходу або вже за ним.

Для LONG це нижня тінь, для SHORT — верхня. Звичайний відкат або дві помірні свічки не об'єднуються в «ніж». Відкриті й майбутні свічки не підтверджують реакцію. Інші перевірки структури, ризику, сесії, повторних збитків та портфеля залишаються.

Workflow встановлює `BZU_ENTRY_MODE: 'HYBRID'`. Лише прийнятий звичайним планувальником, узгоджений із трендом план A без обмежень може створити **паперову** лімітку заздалегідь. Бал сам по собі дозволу не дає. B+ не створює сліпої паперової лімітки. `PASSIVE_LIMIT` та `LIVE_REACTION` підтримуються; запуск без змінної середовища зберігає сумісний типовий `PASSIVE_LIMIT`.

## Живий радар і графік

Зліпок має `cockpit_schema: 3` та повний `plan_pool`. Між Python-циклами браузер перевіряє кешовані плани за кожним отриманим свіжим котируванням. Спостережений пробій SL списує фізичну зону локально; радар, банер і графік переходять до наступного придатного плану. Відновлення ціни або новий ATR не «оживляють» ту саму списану зону у відкритій вкладці. Серверний журнал не змінюється.

Entry, SL, TP1 та TP2 головного кандидата малюються також для попереднього плану. Entry/SL/TP1 враховуються у масштабуванні. Підписи осі мають пріоритет головного Entry; занадто близькі прапорці можуть приховуватися, а точні ціни всіх рівнів залишаються в легенді та картці. Самі рівні не пересуваються.

`null`, порожні рядки, нульові й булеві котирування не стають ціною 0. Анімація «ціна біля лімітки» потребує справжньої PENDING-лімітки з числовим Entry.

Котирування і M5 запитуються приблизно **кожні 3 секунди**, таймери — щосекунди. Мережа, OKX та фонова вкладка впливають на затримку й повноту спостережень. Формат свічок OKX: https://www.okx.com/docs-v5/en/#rest-api-market-data-get-candlesticks .

Для локального сигналу потрібні спостережений підхід із зовнішнього боку, реальний дотик, відбій щонайменше `max($0.06, 3 тіки)` у тій самій M5, повернення за Entry та щонайменше три послідовні спостереження. За фактичною ціною реакції повторно перевіряється R:R ≥1.4; відхід від Entry — не більше 0.25 початкового R.

READY означає **локальний відбій за отриманими тиками; M5 ще не закрита**. Відкриття вкладки вже в зоні не відновлює минулу реакцію з OHLC. Розрив понад 15 секунд, застарілі дані, прихована вкладка та зміна M5 припиняють або скидають доказ. READY живе не довше 15 секунд; наздоганяння та повторний сигнал тієї самої реакції блокуються. Звук вмикається кнопкою. Перезавантаження скидає локальну пам'ять.

## Виконання та межі

Проєкт веде сигнальний/паперовий журнал, без авторизованого торгового API. Браузер не відкриває, не закриває й не скасовує біржових угод та не записує ручне виконання у журнал. Локальний сигнал не надсилає Telegram між циклами Actions. Ручні угоди не синхронізуються автоматично з паперовим обліком. Покращення win rate не встановлено.
