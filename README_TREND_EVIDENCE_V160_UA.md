## Встановлення

1. Замінити файли з ZIP у корені репозиторію, зберегти структуру папок. Додати нові Python-модулі і тести. Не видаляти або не замінювати `multi_scanner_memory.json`, `multi_scanner_state.json`.
2. Замінити `.github/workflows/main.yml`. Cron-job.org і workflow_dispatch залишаються без змін.
3. Замінити саме існуючий файл `.github/workflows/replay_h1_v159_replace_v158_coverage_fix.yml` (так він названий у вашому архіві). Не створювати другий H1 workflow. Додати `.github/workflows/research_alpha_v160.yml`.
4. Запустити BZU MULTI v16.0 Trend Evidence & Alpha Research. Після публікації Pages оновити вкладку Cmd+Shift+R. Дослідницькі дані залишаються у згорнутому розділі.
5. Нові дослідницькі портфелі за замовчуванням працюють паралельно у PAPER. За потреби GitHub variable `BZU_V160_RESEARCH=false` вимикає нові входи в них, але старі позиції супроводжуються до закриття. Основні M1/M5 і H1 Peak не залежать від цього перемикача.

## Історичні тести

H1 workflow: BZU v16.0 H1 Portfolio research. Для відтворення вибрати start 2026-11-08, end 2026-11-28, strict, development, spread_bps 0. Найцікавіший профіль H1_FLEX_PURE. Попередня v15.9 контрольна історія всіх 59 угод відтворена ідентично. Порівняння зі збільшеними витратами до 0.05% на сторону: H1_FLEX_PURE +6.0240 USDT, PF 1.299. Жодна модель не досягла 20 USDT за тиждень.

Новий workflow BZU v16.0 M1 M5 nine-family research: start/end як вище, mode `candidates` для аудиту всіх дев'яти сімейств, `candidates_and_rolling` для додаткового повного replay фактичних слотів і rolling Meta, split 2026-11-21. Експортує поактивні записи, `ALPHA_AUDIT_REPORT.json`, (якщо обрано) `MEXC_REPLAY_REPORT.json`, свічки, кроки ціни й обсягу контрактів. Кандидатний аудит не портфель: холодний детектор без історії, всі виявлені маршрути, окремі статичні SL/TP, без зайнятості слотів, без навчання. Дослідницькі відхилення допускаються до альтернативної оцінки лише за фізично коректної геометрії; неможливі угоди не моделюються. LIMIT має пройти на тик за ціну заявки; невиконані заявки не є виграшами, їхній результат можливості 0R. Неоднозначні, пропущені та незавершені мітки виключаються із чистих метрик. Горизонт 18 годин. Результати групуються за активом, напрямком, TF, сімейством і варіантом; середній R за епізодом не є портфельним PnL. Витрати MARKET 0.03% на сторону, LIMIT 0.02% на вхід, 0.03% на вихід. Funding, історична книга ордерів та точне біржове виконання відсутні. Повний 20-денний replay rolling-слотів локально не завершено; робочий workflow додає його окремо.

## Незалежний період

Всі поточні історичні тести є повторним дослідженням вже використаних даних. Нові правила не переводяться в Active. Коли накопичиться нова історія, запустити `validation_mode=forward` і `coverage_mode=strict` на **2026-11-28 — 2026-12-05 UTC** (не раніше завершення цього інтервалу), профілі PEAK_CURRENT, H1_FLEX_PURE, H1_HA. Guard не дозволяє тесту з позначкою forward починатися раніше 2026-11-28 або тривати менше 7 днів. Це механізм перевірки нового часового відрізку, не доказ незалежності від майбутніх рішень дослідника. Не підбирати параметри по forward-результату і повторно називати його незалежним. Бажано надалі перевірити декілька нових тижнів та обидва напрямки ринку. Поки прибутковість і 20 USDT/тиждень не доведені, не переходити до реальної торгівлі.
