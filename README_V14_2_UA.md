# BZU v14.2 Pro Cockpit & Organic Execution

Розпакуйте архів у корінь чинного репозиторію зі збереженням шляхів. Файли стану й журналу, історія угод та секрети залишаються у вашому середовищі.

У режимі GitHub Actions запустіть наявний workflow вручну, щоб опублікувати перший зліпок v14.2. У режимі постійного воркера перебудуйте контейнер через `docker compose up -d --build`. Параметри воркера наведені у `README_V14_1_UA.md`.

- Тактичний радар показує одну головну картку й до трьох резервів зі скорингом від 60 і R:R від 1.35. Банер і графік беруть той самий план. У діапазоні радар показує розраховані межі.
- Стан браузерної симуляції PAPER прив’язаний до інструмента, ID сигналу й хвилини події та відновлюється після перезавантаження. Серверний журнал звіряє виконання за своїми котируваннями й закритими свічками.
- Новий LIMIT розраховується від фіксованої структурної ціни й потребує 1.40R. Після виставлення поріг скасування через найближчу структурну перешкоду становить 1.15R. Інші причини скасування оцінюються окремо.
- Підтверджений сетап у межах 0.20 ATR від входу може виконатися по MARKET за поточним ask або bid, якщо ціль дає щонайменше 1.35R. MARKET посередині діапазону заблоковано, за винятком підтвердженого пробою попередньої межі.
- У вихідному архіві GitHub Actions запускається за п’ятихвилинним розкладом. Браузер оновлює радар кожні 3 секунди. Telegram має один регулярний звіт на 15-хвилинний слот.
