# Оновлення бота до v12.2

Ціль цієї версії — якісніший відбір лімітних входів. **Win rate 70%+ поки не підтверджений історичною перевіркою.** Повний `bot_oneshot.py` збережено: 734 863 байти, усі 24 оригінальні детектори. Малий розмір ZIP означає стиснення файлів.

## Файли для GitHub

Розпакуйте весь архів і завантажте файли за такими шляхами. Для двох YAML-файлів важливе розміщення в `.github/workflows/`.

| Шлях у репозиторії | Дія | Призначення |
| --- | --- | --- |
| `bot_oneshot.py` | Замінити | Повне ядро з усіма 24 сетапами |
| `full_limit_engine.py` | Замінити | Відбір, два місця для ордерів, супровід |
| `test_full_limit_engine.py` | Замінити | Перевірки ордерів, журналу, сумісності |
| `.github/workflows/main.yml` | Замінити | Робочий запуск кожні 15 хвилин і збереження пам’яті |
| `signal_quality.py` | Додати | Підтвердження входів і статистичний відбір |
| `test_signal_quality.py` | Додати | Перевірки нового відбору й дослідження |
| `research_validate.py` | Додати | Історичне порівняння v12.1 та v12.2 |
| `research/baseline_v12_1.py` | Додати | Зафіксована попередня версія для порівняння |
| `.github/workflows/ict_research.yml` | Додати | Окремий ручний запуск історичної перевірки |
| `setup_preservation_manifest.json` | Залишити; додати, якщо відсутній | Контроль збереження оригінальних детекторів; копія є в ZIP |

`GITHUB_INSTALL_UA.md`, `SETUP_RULES_UA.md`, `VALIDATION_UA.md` — інструкції; можна також завантажити до кореня репозиторію. Усі Python-файли з таблиці потрібні разом: робоча перевірка імпортує й модуль дослідження.

**Збережіть свої `last_signal_v6_4.json` і `signal_journal_v6_4.json`.** У ZIP немає порожніх файлів пам’яті чи журналу. Програма доповнює поточний стан, супроводжує вже відкриті ордери за їхніми рівнями й застосовує новий відбір до наступних входів. Не змінюйте ризикові параметри під час відкритої угоди: це перевіряє наявний механізм сумісності стану.

## Робочий запуск

Команда залишилася:

```bash
python bot_oneshot.py --notify
```

Робочий workflow зберігає звичайний 15-хвилинний розклад, блокування паралельних запусків і два файли стану. Новий облік альтернативних сценаріїв знаходиться всередині пам’яті; окремий commit для нього не потрібен. Telegram-секрети залишаються в GitHub Actions secrets. Tick для live-запуску береться з OKX, тому старе значення `PRICE_TICK_SIZE=0.001` не підміняє біржове `0.01`.

Максимум два зайняті місця: очікування входу, відкрита позиція або непідтверджене виконання. Частковий тейк не звільняє місце. У повідомленнях залишилися номери ордерів, фактичний SL, позначки досягнутих TP і фінальний результат після закриття. Розмір депозиту/позиції не додавався.

## Як перевірити ціль 70%

1. Після завантаження файлів відкрийте **Actions → ICT Research — перевірка цілі 70% → Run workflow**.
2. Залиште 90 днів історії. Допускається 30–180 днів; інструмент береться з тієї самої змінної `OKX_INST_ID`, що й у робочого бота.
3. Після завершення завантажте artifact `ict-quality-research-…` і відкрийте `validation_UA.md`. `validation.json` містить угоди та результати кожного періоду, `candles.json` — вихідні дані.
4. Зелений workflow означає завершений розрахунок. Перевіряйте саме статус у звіті: `TARGET_NOT_CONFIRMED` означає, що ціль не підтверджена.

Дослідження читає публічну історію OKX, не надсилає Telegram-повідомлень і не змінює робочий журнал. Якщо OKX поверне HTTP 403 або історія має пропуски, job завершиться помилкою з поясненням; він не видасть вигадану статистику. Успішний доступ з GitHub ще не перевірений.

`quality_model.json` створюється лише після історичного розрахунку й не встановлюється автоматично. За потреби завантажте саме отриманий файл у корінь репозиторію. Бот перевіряє його стратегію, інструмент, tick, комісії та контрольну суму. Несумісна модель не використовується; супровід чинних угод продовжується, причина записується в Actions і пам’ять. Файл з іншими налаштуваннями потрібно перерахувати, а не редагувати вручну.

Без моделі бот працює за підтвердженнями свічок і накопичує результати окремих сценаріїв. Поки відповідна вибірка мала, це початковий відбір із невідомою ймовірністю успіху, а не обіцянка 70%.

## Локальні команди

```bash
python bot_oneshot.py --self-test
python bot_oneshot.py --legacy-self-test
python research_validate.py --download --days 90 --output research_output
```

Для вже збереженої історії:

```bash
python research_validate.py --data research_output/candles.json --output repeat_research
```

У дослідженні використовуйте ті самі ставки комісій і налаштування, що у live. `research/baseline_v12_1.py` залиште без змін: його контрольна сума захищає чесність порівняння.
