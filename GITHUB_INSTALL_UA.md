# Повний ICT LIMIT bot v12 — встановлення

Ця версія побудована з повного `bot_oneshot(9).py`. Усі 24 оригінальні детектори збережено; перевірка порівнює їхній AST з оригіналом. Новий модуль керує спільним відбором та життєвим циклом лімітного плану. Старі функції залишені для сумісності й регресійних перевірок; виробничий запуск викликає `full_limit_engine.py`.

## Файли для GitHub

Розпакуйте ZIP. Збережіть наведені назви й шляхи від кореня репозиторію.

| `bot_oneshot.py` | Замінити попередній основний файл повною версією v12. |

Попередні `test_bot_oneshot.py` і workflow v11 не є перевірками/запуском v12. Вимкніть старий розклад у Actions, щоб два workflow не працювали з тими самими файлами стану. Решта файлів вашого репозиторію не входить до цього пакета.

## Стан і журнал

Зробіть резервну копію ваших `last_signal_v6_4.json` та `signal_journal_v6_4.json` перед встановленням. При звичайному оновленні залиште їх у корені репозиторію. Нове ядро зберігає історію журналу, невідомі поля й повну копію попереднього стану під `legacy_snapshot`. Воно переносить один чинний ордер або відкриту позицію, зберігаючи ціни та строк ордера.

Стани повного ORIGINAL/ORGANIC бота та попередньої малої v11 розпізнаються. Невідомий або пошкоджений стан викликає помилку замість тихого обнулення. За кількох старих ордерів або відкритої позиції разом із невиконаними ордерами потрібна звірка; усі старі записи зберігаються. Для ORIGINAL збережена геометрія позиції переходить на нову політику супроводу. Архів старого стану також містить його початкові поля супроводу.

Для **чистого початку**, коли старих відкритих позицій/ордерів немає, скопіюйте обидва файли з `clean_start/` у корінь. Це свідомий початок нового обліку; ваша резервна копія міститиме стару історію. Файли в `clean_start/` самі по собі не підмінюють поточний журнал.

## GitHub Actions

У Settings → Secrets and variables → Actions додайте secrets:

- `TELEGRAM_TOKEN`
- `TELEGRAM_CHAT_ID`

За потреби додайте repository variables:

| Змінна | Типове значення | Значення |
| --- | --- | --- |
| `OKX_INST_ID` | `BZ-USDT-SWAP` | Точний доступний інструмент OKX. |
| `PRICE_TICK_SIZE` | `0.001` | Реальний крок ціни цього інструмента. |
| `MAKER_FEE_RATE` | `0.0002` | Комісія входу дробом: 0.0002 = 0.02%. |
| `TAKER_FEE_RATE` | `0.0005` | Комісія виходу дробом: 0.0005 = 0.05%. |

Бот перевіряє доступність інструмента й фактичний `tickSz` у публічному API. Якщо змінюєте інструмент, використовуйте окремі файли стану та журналу. Якщо змінюєте параметри з відкритим планом, спочатку завершіть його життєвий цикл — геометрія чинного плану не перераховується потай.

Дозвольте workflow запис у репозиторій: Settings → Actions → General → Workflow permissions → Read and write permissions. Захист гілки також має дозволяти збереження стану обраним способом. Workflow запускається з default branch, спершу виконує 69 нові тести та 49 старих перевірок сумісності, потім один цикл бота й зберігає стан/журнал комітом.

Запустіть Actions → Full ICT Limit Bot v12 → Run workflow. Перевірте успішні кроки тестів, повідомлення Telegram і коміт зі станом. Плановий cron — `*/15 * * * *`; GitHub може затримувати або пропускати запуски. TTL, усі закриті 3m-свічки між звітами та дозавантаження історії враховуються. Відсутня історія виконання призупиняє рішення.

## Команди

Python 3.11 або новіший; сторонні пакети не обов'язкові. За відсутності `requests` основний файл використовує стандартну бібліотеку.

```bash
python bot_oneshot.py --self-test
python bot_oneshot.py --legacy-self-test
python bot_oneshot.py --notify
python bot_oneshot.py --audit-journal signal_journal_v6_4.json --output audit.json
python bot_oneshot.py --replay candles.json --output replay.json
```

`--legacy-self-test` перевіряє збережені старі функції, включно зі старими правилами PROBE. Ці правила не керують новим виробничим циклом.

Офлайн-формат `candles.json`: `candles` з масивами `3m`, `15m`, `1H`, `4H`; кожна свічка має `ts` у мілісекундах часу **відкриття**, `open`, `high`, `low`, `close`, `volume`, `confirmed`. Для SMT можна додати `smt_candles_15m`. Для періоду оцінки — `start_ts` і `end_ts`; раніші свічки потрібні для прогріву. Replay використовує лише свічки, закриті до поточного кроку, та рішення раз на 15 хвилин.

Для знімка ринку команда `--snapshot snapshot.json` додатково потребує `now`, `price`, `bid`, `ask`, `ticker_ts`, `instrument`, `trusted: true`. Без `--notify` цей режим не надсилає повідомлень. Вкажіть окремі `SIGNAL_MEMORY_FILE` та `SIGNAL_JOURNAL_FILE` для дослідів.

`--ack-unresolved` застосовуйте після фактичної звірки ордерів: він підтверджує вирішення невідомої послідовності подій і дозволяє нові плани. Це ручне підтвердження, а не автоматична перевірка біржі.

## Поведінка v12

- Аналіз закритих 3m/15m/1h/4h; усі 24 детектори перевіряються кожного здорового циклу.
- Сетапи дають гіпотези; спільне ядро перевіряє реальну лімітну ціну, структурний стоп, досяжність і чистий R:R після витрат.
- Збіги рівня/напрямку об'єднуються. Повторення однієї сім'ї не створює багато незалежних голосів. Близькі за оцінкою протилежні сценарії дають `DIRECTION_CONFLICT`; сильніший може бути обраний.
- Різні напрямки 1h/4h оцінюються для конкретної сторони. Два HTF проти входу потребують початкового reversal-сетапу з підтвердженням напрямку 15m/3m.
- Один зарезервований ліміт або одна позиція. Новий сильніший сетап не переписує чинний ордер.
- Немає автоматичного закриття за старим PROBE/no-followthrough або лише через новий протилежний сетап. Є SL, часткові TP, зміна стопа на момент звіту та внутрішньоденний строк позиції.
- TP1: до 2R та до найближчої структурної перешкоди; TP2/TP3: наступні структурні рівні з обмеженнями 3R/4R. Якщо подальших рівнів немає, виходи об'єднуються. Частки 65%/20%/15% стосуються **закриття вже відкритої позиції**, а не частки депозиту на вході. TP0 — маркер, без часткового закриття.
- В повідомленні немає обсягу, плеча або частки депозиту. Розмір ви задаєте під час виконання на біржі.
- Перед новими входами: типовий ліміт 5 виконаних входів/день, 3R суми збитків/день, строк ліміту до 90 хв, позиції до 6 год, закриття до 23:00 Europe/Kyiv. Ліміти дня спираються на новий ledger; історичний ORIGINAL-журнал не стає новими входами заднім числом.

Це сигнальний/PAPER бот: він не надсилає ордери на біржу і не знає фактичного виконання. Стопи/цілі мають діяти на біржі між повідомленнями. Score — оцінка умов, а не перевірена ймовірність виграшу. Реальний win rate нової архітектури потрібно виміряти на ринкових даних та окремому періоді перевірки.
