# BZU v12.20.0 — підсумок виправлень і обмеження валідації

**База:** v12.19.1 поверх BZU-Signal-Bot-main(7).zip. **Нова версія:** `full-ict-v12.20.0-reviewed-short`.

## Реалізовані зміни

1. Додано Docker Compose для існуючого постійного `continuous_worker.py`, з розкладом по **закритих 3m-свічках** й окремим звітом у 15m-бакеті. Workflow GitHub залишається **кожні 5m** як альтернативний спосіб запуску, а не одночасний другий writer. Встановіть `BZU_EXECUTION_MODE=WORKER` і розгорніть контейнер на постійному сервері — без цього фактичних 3m перевірок немає.
2. Після `LIMIT_UNREACHABLE` застарілий anchor отримує `REJECTED` tombstone у `anchor_memory`. Повторно отримати вхід зі старого рівня не можна без нової підтвердженої структурної події; на кожному скані незалежний BOS/FVG детектор аналізує всі свіжі 3m-свічки. Ніякого перенесення ліміту за поточною ціною немає.
3. `STRICT` тепер використовує явний список допустимих playbook-сімейств для всіх **24 ICT-сетапів**, з обов'язковим збігом `setup_type`, LONG/SHORT, валідності структури, часу та стопа. Прямі `STRATEGY_EVENT` підтверджуються оригінальним ідентифікатором події та proxy setup. Відсутня сім’я = відмова.
4. Мінімальний SL **1%**, TP1 **2%** і комісії збережені. Раніше чинний `LIMIT_MAX_STOP_ATR=1.90` збільшено до **4.00** в production конфігурації (обмежено верхньою межею 6.0): ціль залишається структурною, а не вигаданою. Збільшення ATR-стелі може пропустити ширші стопи, тому потрібен додатковий моніторинг фактичного ризику.
5. Перераховано 63 історичні SHORT BOS/FVG сигнали за старими даними, але з новою мінімальною 1%/2% проксі-геометрією, maker/taker fee і slippage. Проведено контроль проти сильних зустрічних зон лише на point-in-time закритих свічках; майбутні свічки використовувалися **лише** для постфактум міток наслідків.

## Перевірки (локальні)

- `python bot_oneshot.py --self-test` — **534/534 OK**.
- `python bot_oneshot.py --legacy-self-test` — **49/49 OK** (2 історичні fixture-еталони виконано із старою межею 1.90 ATR; діюча межа перевіряється окремо).
- 24×3×2 перевірки таблиці підтверджень, тест недопустимих сімейств і unknown setup, tombstone, stop/TP minima, worker, stop-first replay.
- Історична STRICT/zone діагностика за 12 датами: **313 SHORT шляхів**, **0 схвалених**. Це не повна хронологічна симуляція всіх торгових циклів.
- Серед 63 структурних SHORT-подій **62** мали сильний зустрічний бар’єр перед мінімальною ціллю за моделлю зон, лише **1** — без такого близького бар’єра. Окремий контрфактичний replay проксі-виходів не довів безпеку послаблення зони. Робочий захист **не вимкнутий**.

## Що залишається непідтвердженим

- **Немає гарантованих 3m входів лише в GitHub Actions.** Потрібен увімкнений постійний worker та час виконання одного циклу менше 3 хвилин, інакше деякі закриття свічок будуть запізнілими. Воркера не розгорнуто на зовнішньому сервері цим архівом.
- Історичні 63 події — **проксі-дослідження, не виконані біржові угоди**. У ньому немає повного order-book, двох слотів, усіх фільтрів і підтверджених структурних TP. 12 вибраних зрізів та три календарні підвибірки не доводять прибутковості.
- **Реальні OKX ордери не відправляються**: код цієї гілки веде PAPER-облік.
- Ціль 70%+ win rate **не підтверджена**; немає дозволу знімати критичні фільтри на підставі цього тесту.

**Висновок:** кодові виправлення внесені; тестова регресія успішна. Своєчасність залежить від окремого розгортання та продуктивності хоста, а ефективність SHORT ще вимагає повного незалежного forward/chronological replay.
