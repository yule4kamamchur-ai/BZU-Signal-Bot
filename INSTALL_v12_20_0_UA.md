# BZU v12.20.0 — встановлення змін

Скопіюйте змінені файли з архіву поверх файлів репозиторію, зі збереженням вкладених шляхів (`.github/workflows/main.yml`). Збережіть власні файли стану та не перезаписуйте їх даними з архіву.

## Варіант A: GitHub Actions

GitHub cron не підтримує надійний цикл кожні 3 хвилини; workflow залишається на **5-хвилинному** інтервалі, а повідомлення — максимум раз на 15 хвилин. Затримки планувальника можливі. Реальне виконання ордерів OKX не ввімкнене: облік PAPER.

## Варіант B: реальна перевірка на кожному закритті 3m

1. Підготуйте постійно працюючий Linux-хост із Docker Compose (сервер/VPS).
2. Перенесіть `last_signal_v6_4.json`, `signal_journal_v6_4.json`, `market_history_v12.json`, `research_market_v12_6.json` до `data/` **перед першим запуском**. Не запускайте воркер із порожнім станом, якщо потрібно зберегти відкриті PAPER-позиції.
3. `cp .env.worker.example .env`; заповніть TELEGRAM_TOKEN, TELEGRAM_CHAT_ID; не публікуйте `.env`.
4. Вимкніть 5m GitHub writer: у Settings → Secrets and variables → Actions → Variables створіть `BZU_EXECUTION_MODE=WORKER`; дочекайтеся завершення запущених GitHub workflow.
5. `docker compose up -d --build`; перевірте `docker compose logs -f --tail 50`.
6. Потік сканує після закриття кожної 3m-свічки і надсилає звіт в окремому 15m-бакеті. Це best effort: мережеві затримки та тривалий цикл можуть пропускати інтервали.

Для повернення на GitHub: зупиніть контейнер, синхронізуйте стан із `data/` до робочого репозиторію, після цього приберіть змінну `BZU_EXECUTION_MODE`. **Не запускайте два процеси одночасно**.

## Торгові правила

Мінімальний SL=1%, мінімальний TP1=2%, комісії враховані. `LIMIT_MAX_STOP_ATR=4.0` піднімає стару межу 1.9ATR, але геометрія стопу, неподолані зустрічні зони й нетто RR продовжують блокувати непридатні входи. 24 детектори з власними ICT-контрактами, незалежний `STRICT`, перерахунок застарілих рівнів після **нової** підтвердженої події. Це ще не доказ прибутковості/70% win rate.

Деталі перевірок, їх обмеження й результати див. `VALIDATION_v12_20_0_UA.md`.
