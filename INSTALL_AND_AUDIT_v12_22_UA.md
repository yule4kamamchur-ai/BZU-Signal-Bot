# BZU v12.22.0 — виправлення входів і супроводу

Пакет містить тільки змінені файли, нові перевірки та результати аудиту.
Версія запуску й ядра: `full-ict-v12.22.0-precision-protection`.

## Встановлення

1. Розпакуйте ZIP. Замініть файли в репозиторії за тими самими відносними шляхами.
2. Обов’язково оновіть `.github/workflows/main.yml`. Кореневий `WORKFLOW_main.yml` є його тотожною копією для зручного перенесення тексту в редактор GitHub; він сам не запускає Actions.
3. Усі 14 змінених робочих файлів потрібно перенести разом. Їхній перелік і SHA256 наведені у `CHANGED_FILES_v12_22.json`.
4. Нові параметри workflow: `MIN_SETUP_SCORE=65`, `BZU_MAX_STOP_ABSOLUTE=0.75`; очікувана версія відповідає файлам ядра.
5. Після заміни можна виконати перевірку нижче та запустити звичайний workflow. У цьому сеансі код не встановлювався у GitHub і повідомлення в Telegram не надсилалися.

Розклад залишається `*/15 * * * *`: один кінцевий запуск кожні 15 хвилин і захист від повторного повідомлення в тому самому 15-хвилинному інтервалі. GitHub Actions може стартувати із затримкою; точність доставки до секунди цей розклад не гарантує.

Файли поточного стану, журналу та ринкових архівів у пакет не включені. Існуючі відкриті позиції з політикою v12.21 продовжують свій попередній контракт виходу. Зміна цін SL/TP заднім числом не проводиться. Під час міграції старі дослідницькі спостереження зберігаються в архіві окремо від нової політики.

## Що реалізовано

| Правило | Поведінка v12.22 |
|---|---|
| Один вхід | Один ордер на 100% розрахункового ризику; другої половини входу немає |
| Вузька зона | За ширини до 0.35 ATR15 використовується проксимальна межа з буфером 0.02 |
| Широка зона | Вхід на 50% глибини; це вибрана в межах чек-листа точка 35–50% |
| Стоп | За структурною інвалідацією, дистальною межею та доступним підтвердженим свінгом із буфером 0.20 ATR15; мінімум 0.20 за замовчуванням |
| Дорогий стоп | За ризику понад 0.75 вхід поглиблюється до середини; якщо цього недостатньо — відмова. Стоп до ціни не підтягується |
| Беззбиток | Після +1R без зменшення обсягу; рівень покриває налаштовані комісії та прослизання. Новий SL діє з наступної свічки виконання |
| TP1 / TP2 | TP1 від 1.4R: 50% фактично відкритого обсягу. TP2: решта 50%, 2.5–3R із наявним структурним простором |
| Імпульс до зони | Одне або два послідовні несприятливі тіла понад 1.8 ATR15 із закриттям біля екстремуму переводять сценарій у спостереження |
| Вихід із гальмування | Пізніша закрита 15m свічка має доторкнутися зони й показати відкуп/відхилення. Свічка імпульсу не підтверджує сама себе |
| Catch-up | Поточний вхід потребує безперервної 1m історії дотику й останньої закритої 5m/15m свічки в напрямку угоди за правильною межею зони; актуальна ціна також має залишатися з потрібного боку |
| Мінімум якості | 65 балів; 80 для контртренду. Обов’язково sweep або пов’язаний у часі displacement + BOS + свіжа FVG |
| Ваги | Зона 25; sweep 30; displacement/BOS/FVG 25; HTF 10; сесія 5; позитивна модель/edge 5 |
| Походження зони | Імпульс саме з цієї зони повинен пробити локальний рівень, відомий до формування; пізніший сторонній BOS не зараховується |
| Локальний конфлікт | Два послідовні зниження/підвищення підтверджених свінгів і ціна за EMA50 на 15m створюють PULLBACK_PHASE; звичайний вхід проти локального руху очікує CHoCH або досягнення HTF POI |
| Контртренд | Високого бала недостатньо: потрібен підтверджений розворот на 1H або досягнута HTF зона зі sweep → MSS на 15m, далі поріг 80 |
| Після стопа | Цей напрямок заблокований на 60 хвилин. Виняток — оцінка від 82 і новий підтверджений sweep, що виник після закриття збиткової угоди |
| Два місця | До двох окремих лімітів при відсутності позиції; після відкриття позиції нові входи не додаються, інші ліміти скасовуються на доступній межі перевірки |
| Сусідні зони | Зберігається найкращий перевірений план; бали кількох залежних детекторів більше не складаються |

Catch-up перевіряється у `setup_scanner.py` і фактичному спільному планувальнику `bzu_policy.py`: сюди потрапляють і події з `strategy_direct_entries.py`. Супровід нового контракту виконується у `bzu_policy.manage`, який викликає `full_limit_engine.manage_bar`; тому дублювання логіки в `position_monitor.py` не потрібне.

## Часові обмеження

- 21:30–03:00 UTC: нові входи заблоковані, невиконані ліміти нової політики скасовуються. Це правило відоме до початку свічки і враховується навіть під час пізнішого відновлення пропущеного інтервалу.
- 09:30–09:45 за Нью-Йорком у будні: нові сліпі входи призупинені; UTC зміщується автоматично через `America/New_York` (13:30 влітку / 14:30 взимку).
- Після завершення вікна сценарій знову проходить усі структурні перевірки. Кожен запис результату зберігається один раз після остаточного виходу, включаючи обидві частини фіксації та витрати.

09:30 Нью-Йорка названо в коді вікном ризику США. Це заданий фільтр, а не твердження про відкриття нафтових ф’ючерсів саме в цей час. ICE наводить для Brent денні години Лондона, а CME для WTI — електронну сесію з окремою щоденною перервою. Розклад торгів OKX не підміняється календарем цих бірж.

Джерела для звірки термінів: [ICE Brent](https://www.ice.com/brent-crude), [CME WTI](https://www.cmegroup.com/education/courses/introduction-to-crude-oil/product-overview/wti-overview).

Старі набори містять очікування іншого розкладу, допуску без підтвердженого походження, split-entry, 55 балів та виходу на 1R. Результат 53/53 не видається за успіх усього набору.
