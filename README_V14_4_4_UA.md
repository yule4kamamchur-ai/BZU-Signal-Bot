# BZU v14.4.4 · калібрація Cold Start

Патч встановлюється поверх v14.4.3. Перенесіть файли в однойменні місця одним комітом, включно з `.github/workflows/calibrate_meta_model.yml` та `.github/workflows/main.yml`. Поточні журнали й ринковий архів беруться зі встановленого репозиторію.

## 11. Causal Replay

У GitHub Actions відкрийте **BZU Meta Calibration → Run workflow**. Типові параметри беруть публічні свічки OKX за 180 днів і сканують їх кожні 15 хвилин. Параметр `days` підтримує до 365 днів. Межа історії враховує дату лістингу та прогрів. Джерело `archive` відтворює наявні в репозиторії котирування за їхніми реальними часовими мітками. Режим `5` хвилин доступний для щільнішого сканування завантажених свічок і потребує більше часу.

Реплей викликає `full_limit_engine.run_cycle` і використовує лише свічки та котирування, доступні на момент скану. Для завантаженої історії котирування оцінюються за закриттям M1 з модельним спредом. Звіт містить кількість сканів і розміток, пропуски, результати та Brier score. Три послідовні вікна в останніх 30% історії перевіряють модель на пізніших незалежних епізодах. У навчання кожного вікна потрапляють лише мітки, відомі до його початку. Для публікації потрібно щонайменше 20 незалежних перевірочних міток у двох або більше вікнах та покращення Brier score проти загальної частоти виграшів при результаті щонайменше на рівні евристики.

Запуск зберігає `meta_priors.json`, звіт і мітки в артефакті Actions. Якщо перевірка успішна й увімкнено `publish`, workflow також оновлює `meta_priors.json` у корені основної гілки. Ринковий бот підхоплює файл під час наступного скану. Калібрація працює через публічний API й незалежно від торгівельного workflow.

## 12. Shadow Ledger

`shadow_trades` реєструє кожен унікальний допущений торговий план до перевірки зайнятості портфеля. MARKET бере котирування моменту рішення. Для LIMIT спочатку має статися модельоване заповнення після постановки. Новий журнал використовує закриті M1 для фіксації TP, SL або часового бар’єра від моменту входу. За замовчуванням часова межа становить шість годин. Результат враховує налаштовані комісії та модельне проковзування.

У журналі видно `MFE`, `MAE`, `Net R`, сетап, напрям 4H, місце в діапазоні та сесію. Незаповнена заявка або розрив M1 має окрему причину й не отримує ярлика виграшу чи збитку. За подвійного торкання після входу в нерозрізненій M1 пріоритет має SL. Результати тіньових угод зберігаються в `full_v12.shadow_trades` основного журналу. Вони не займають портфельний слот.

## 13. Байєсівська оцінка

Контекст використовує `setup × side_4h × range_bucket × session`. У рідкісних контекстах історична оцінка наближається до оцінки ширшої групи. Історичний апріор має вагу `N₀ = 30`. Нові завершені результати з поточного портфельного й тіньового журналів після дати історичної калібрації мають вагу `0.985` за кожну добу давності. Якщо портфельна й тіньова угода описують один епізод, пріоритет має портфельний результат. Поточний портфельний журнал використовує виконання PAPER-стратегії. Для підтвердженого біржового PnL потрібна окрема звірка.

Оновлений `meta_prob` керує рівнями `0.35× / 0.65× / 1.00×`. Нижче `0.50` вмикається Confirmation. Ліміти ризику для пізніх і контртрендових угод враховуються додатково. За відсутності валідованого сумісного файлу діє поточна евристика. Статус видно в полі `meta_calibration_status` дашборда.

## Локальна перевірка

```bash
python bot_oneshot.py --self-test
python -m unittest test_meta_calibration
node test_live_terminal_ui.cjs
python calibrate_meta_model.py --archive research_market_v12_6.json --days 2 --end-ms 1793815200000
```

У короткому прогоні на реальних котируваннях з архіву 4 листопада отримано 52 скани, 2 закриті портфельні угоди та 8 унікальних міток після зведення журналів. Через доступність M1 16 сканів мали статус DATA_HOLD. На відкладеній перевірці доступна одна незалежна мітка. Такий результат придатний для перевірки конвеєра, а активація моделі потребує ширшої вибірки.
