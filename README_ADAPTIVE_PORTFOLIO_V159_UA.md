## Виконання H1/M15
- Мінімальний номінал 5 USDT; мінімальний доступний та фактично зарезервований стоп-ризик із витратами 0.25 USDT. Це локальні правила виконання BZU, а не твердження, що біржа має однакові мінімуми на всі контракти.
- Публічний `/api/v1/contract/detail`, який уже використовувався для кроку ціни, також повертає `contractSize`, `volUnit`, `minVol`, за наявності `maxVol`, `maxLeverage`. `qty = contracts * contractSize`. Округлення контрактів вниз через Decimal, з повторною перевіркою ризику та номіналу. Не вигадуємо крок обсягу з кроку ціни.
- Нові H1/M15 позиції на живому сканері та workflow replay вимагають метаданих контракту. Якщо їх немає — діагностика, без нового модельного входу. Існуючі позиції продовжують супроводжуватись. Локальний replay старого CSV без метаданих дозволено тільки як явно позначений continuous research proxy (не відтворення виконуваного контракту MEXC).
- Зберігається 3% спільного стоп-ризику на кожному окремому PAPER-рахунку, 5x стеля номіналу, кластерні ліміти. Додано перевірку спільної модельної маржі з урахуванням `maxLeverage`. Гепи, funding, ліквідація та реальне виконання не гарантуються цим бюджетом.
- Закриті угоди та старі нормальні відкриті позиції не змінюються. Лише legacy позиції, у яких **одночасно** номінал та резерв ризику не більше 1e-8 USDT, виключаються з відкритих як числовий артефакт. Їх початкові записи збережено у `voided_numerical_positions`, без нарахування штучного PnL. Історичні закриті мікропозиції залишаються в старій статистиці; `legacy_subminimum_retained` та `v159_closed_stats_retained` відділяють їх від нових. Не видаляються реальніші старі позиції нижче нового мінімуму.

## Контроль та експерименти
- PEAK_CURRENT: попередній Donchian(30), SL 2.5 ATR(H1), Peak trail 3.5 ATR(H1), без TP. Змінено тільки правила виконання та додано опис ознак. База для нового replay.
- CLOSE_PRIOR: контрольна альтернатива H1 Close/Prior ATR.
- RANGE_ONLY: попередній M15 Reclaim, окремий контроль.
- MIXED_PEAK_RANGE: історичне порівняння на вимогу; у живому PAPER наявний старий змішаний рахунок лише супроводжує старі позиції, не відкриває нові.
- ADAPTIVE_H1: окремий challenger. Оцінює тіло, закриття, силу пробою, ефективність руху, режим. Вибирає Peak/Close на момент входу, спираючись на згладжені власні спостереження, а за їх браку — дослідницьку евристику. Не підглядає у майбутнє і не перемикає трейлінг заднім числом. Це не доведений детектор справжнього пробою.
- EARLY_H1_M5: окремий challenger з базовими рейтингом і Peak trail; перетин попереднього каналу H1 на закритій M5 без обов'язкового очікування завершення поточної H1. Дві останні закриті M5, перевірка збереження рівня, давності та відстані ціни. Підтверджений H1 лишається доступним. Наявний M1/M5 Alpha не блокується.
- RANGE_LOCK_ONLY: тільки історична абляція нової політики виходу, без зміни розподілу капіталу. Після +0.75R максимального руху, на закритті M15, пробує захистити +0.10R після оцінених round-trip витрат. Якщо на той момент ціна вже за новим стопом, вихід за відомою ціною закриття, а не вигаданий прибуток. Новий стоп не застосовується до попередньої M1. TP та первинний SL не змінюються.
- ADAPTIVE_RANGE: незалежний challenger з тією ж M15 exit policy, додатковим адаптивним ранжуванням і розміром позиції. Ні один challenger автоматично не переходить у базу навіть при PF >1.10 на одному періоді.
- `ADAPTIVE_H1` і `ADAPTIVE_RANGE`: окрема згладжена оцінка R для активу, напрямку та режиму на власних завершених угодах, з нульовим початковим середнім, вагою 8 умовних спостережень; чужі активи/режими менша вага, протилежний напрямок виключений. Придатні `OBSERVED_M1`, однозначні partial entry зі зниженою вагою 0.25. Не навчається на старих або неоднозначних даних, майбутніх мітках чи інших рахунках. Це дослідницька оцінка, не калібрована ймовірність. Кореляція до 48 синхронних закритих H1 returns (мінімум 16) з урахуванням знаку позицій — м'який штраф за дублювання експозиції. На кожному кроці перераховує виконувані кандидати і ранжує приблизний очікуваний USDT плюс малу евристичну поправку. Негативне очікування не є сигналом до реальної торгівлі; це експериментальний PAPER-контур.
- Усі книги окремі модельні депозити. M1/M5, H1 Peak, H1 Close, M15, challengers не можна підсумовувати як один рахунок $100. Спільний капітал і кореляція реалізовані **всередині** відповідного портфеля, не між усіма незалежними моделями. M1/M5 геометрія v15.8 та Shadow збережені без нової торгової політики.

## Історичний workflow
- Profile default `PEAK_CURRENT`, для зіставлення `CLOSE_PRIOR`, `RANGE_ONLY`, `RANGE_LOCK_ONLY`, `ADAPTIVE_H1`, `EARLY_H1_M5`, `ADAPTIVE_RANGE`, `MIXED_PEAK_RANGE`.
- Дати першої перевірки: 2026-11-08 / 2026-11-28; coverage `strict` якщо потрібен саме цей інтервал, `available` якщо API не надає повний період; spread_bps 0 для порівняння зі старими тестами (не означає реальну нульову вартість спреду).
- Завантажує сім торгових активів + BTC для майбутніх порівнянь. CSV із timestamp, OHLCV, `ticks.json`, `contract_specs.json`, звіт покриття, звіт угод в одному artifact `mexc-v159-<PROFILE>-research`. Попередні CSV накопичуються в кеші, повторні дати не дублюються. Кеш GitHub може бути видалений за його політикою; зберігати артефакти окремо. `contract_specs.json` — знімок на момент завантаження, не історичні характеристики контрактів. Звіт містить SHA256 CSV та SHA GitHub commit, статистику за активом/стороною/режимом/маршрутом.
- Надіслати ZIP з Summary > Artifacts; обов'язково з CSV. Не потрібні токени чи ключі. Для наступної історичної перевірки також провести cost stress зі spread 2–4 bps. Не порівнювати різні дати, витрати або скорочені періоди як однакові тести.
