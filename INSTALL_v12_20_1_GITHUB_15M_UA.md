# BZU v12.20.1 — GitHub Actions, повідомлення кожні 15 хвилин

## Як працює після оновлення

- **Постійний сервер не потрібен.** Єдиний запланований процес — одноразовий GitHub Actions `run-bot`.
- GitHub Actions запускає аналіз раз на **5 хвилин** (`*/5 * * * *`). Кожний запуск використовує лише доступні на той момент закриті 3m-свічки. Це **не** гарантує входу точно після кожної 3m-свічки.
- Лише перший успішний скан у кожному **15-хвилинному інтервалі UTC** формує Telegram-звіт. Решта сканів нічого не надсилають. Дані про вже надісланий звіт зберігаються в `last_signal_v6_4.json` (`last_report_requested_ts`).
- Звіт приходить і без угод. Гарантувати точний час `:00, :15, :30, :45` не можна: GitHub Actions може запускати задачі із затримкою, а Telegram іноді недоступний.
- Немає безперервного сервісу, `docker compose` запускати не потрібно; старі файли worker/Docker залишаються необов'язковими й НЕ використовуються GitHub workflow.

## Що замінити

1. Замінити `.github/workflows/main.yml` у GitHub репозиторії.
2. Замінити `WORKFLOW_main.yml` для синхронності (резервна копія workflow у корені).
3. Існуючі `bot_oneshot.py`, `full_limit_engine.py` і всі торгові файли v12.20.0 **не змінювати**. SL 1%, TP1 2%, 24 ICT-сетапи збережено.
4. Якщо раніше створювали змінну `BZU_EXECUTION_MODE=WORKER`, видалити її в Settings → Secrets and variables → Actions → Variables: тепер вона ігнорується, бо workflow завжди використовує GitHub.
5. Якщо вже розгортали Docker worker/VPS — спочатку **зупинити його**, а вже потім активувати GitHub workflow. Одночасно обидва процеси можуть пошкодити журнал стану.
6. Перевірити, що у GitHub Actions є секрети `TELEGRAM_TOKEN` і `TELEGRAM_CHAT_ID`. За бажанням натиснути `Run workflow` для однієї ручної перевірки, але вона також може надсилати звіт, якщо в поточному 15m інтервалі звіт ще не був сформований.

**Не видаляйте** `last_signal_v6_4.json`, `signal_journal_v6_4.json`, `market_history_v12.json`, `research_market_v12_6.json`. Наявний стан має зберегтися.

## Технічна перевірка

`python -m unittest -v test_v12_20_github_cadence`

Точність 3m-активації, рівно кожні 15m повідомлення без затримок та реальне виконання на OKX **неможливо гарантувати** одноразовими GitHub Actions. Вмикається саме періодичне сканування та звітування, без постійного сервера. Ордери продовжують бути PAPER.
