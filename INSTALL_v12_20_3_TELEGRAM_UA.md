## Перевірка після встановлення
1. У GitHub: **Actions → BZU Auto Bot → Run workflow**.
2. Ручний запуск запитує звіт **відразу**, навіть якщо 15-хвилинний інтервал вже мав плановий звіт.
3. У журналі кроку **Fast scan (closed 3m) with 15m report gating** знайдіть `[TELEGRAM] Message delivered successfully`.
4. Якщо Telegram відмовив, в логах видно HTTP-код і коротку причину, без розкриття токена: `chat not found` — перевірте `TELEGRAM_CHAT_ID`; `bot was blocked` — розблокуйте бота та надішліть `/start`; `Unauthorized` — перевірте `TELEGRAM_TOKEN`.
5. Налаштування секретів: **Settings → Secrets and variables → Actions** (`TELEGRAM_TOKEN` і `TELEGRAM_CHAT_ID`). Не додавайте їх до файлів репозиторію.

## Режим роботи
- GitHub Actions викликає бот **кожні 5 хвилин** для сканування; постійний сервер не потрібний.
- У плановому режимі лише **один новий Telegram-звіт на UTC 15-хвилинний інтервал**. Якщо біржа/Telegram/Actions затримує запуск, точний момент доставки не гарантований.
- Ручний `Run workflow` створює звіт одразу (це свідомий виняток зі звичайного розкладу).
- Якщо звіт не доставився, він залишається в `notification_queue` та повторно надсилається при наступному успішному скануванні, без створення додаткового звіту кожні 5 хвилин.
- Статус успішного виконання GitHub Actions не доводить доставку, поки не видно повідомлення Telegram API.
